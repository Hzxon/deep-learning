# Project Structure

**Purpose.** One page that answers, for any file: *where does it live, who owns it, is it
hand-authored or generated, and can I safely delete/regenerate it?*

**Rule.** Every concept in this repository has exactly **one** canonical file. Before adding
a new Markdown file, script, or config, search this page first. If something already owns
the concept, edit it in place — do not fork a copy "for convenience" or "for legacy paths."
`scripts/check_artifacts.py` enforces this for the four core docs (see §5).

---

## 1. Top-level map

```text
ser_research_full/
├── AGENTS.md                  # Project charter — hand-authored, do not regenerate
├── README.md                  # Human entry point — hand-authored
├── RESEARCH_DESIGN.md         # Literature framing for the thesis — hand-authored
├── RESEARCH_OS_SUMMARY.md     # What the Research OS installed — hand-authored, updated on change
├── CHANGELOG.md               # User-facing release notes — hand-authored, updated on release
├── PROJECT_STATE.yaml         # Stage machine — generated by scripts/workflow.py
├── PRE_TRAINING_AUDIT.md      # Latest pre-training gate audit — generated (absent until run)
├── POST_TRAINING_AUDIT.md     # Latest post-training health audit — generated
│
├── docs/                      # Canonical specifications (§2)
├── .cursor/                   # Research OS automation (§3)
├── config/                    # All hyperparameters — no magic numbers in code (§4)
├── src/ser/                   # Library code — models, data, training, metrics (§6)
├── scripts/                   # CLI entry points — one script per pipeline stage (§7)
├── tests/                     # pytest suite, mirrors scripts/ + src/ser/ (§8)
│
├── data/                      # Raw + processed data (gitignored, machine-specific)
├── artifacts/                 # Per-run engineering outputs (gitignored) (§9)
├── results/                   # Research-facing tables/figures (gitignored) (§9)
│
├── .github/workflows/         # CI (validate.yml, nightly-audit.yml)
├── requirements.txt / pyproject.toml
└── .venv/                     # Local virtualenv (gitignored)
```

**Hand-authored root files never get a duplicate copy anywhere else.** Generated root
reports (`*_AUDIT.md`, `PROJECT_STATE.yaml`)
are overwritten in place by `scripts/workflow.py` and its sub-scripts — treat their content
as disposable evidence of the *last* run, not as something to hand-edit.

## 2. `docs/` — canonical specifications (single source of truth)

| File | Owns | Edited by |
|---|---|---|
| `docs/SER_PROJECT_SPEC.md` | Research design, RQs, preprocessing, features, models, protocols, metrics, Definition of Done | Humans, reviewed via `.cursor/rules/01-project-spec.mdc` |
| `docs/VALIDATION_PROTOCOL.md` | The 8 validation gates, CLI commands, recovery steps | Humans, kept in sync with `scripts/validate_*.py` |
| `docs/WORKFLOW_GUIDE.md` | Stage-by-stage playbook + collaborator onboarding (macOS/Linux/Windows+CUDA), fresh clone → final report | Humans |
| `docs/CI_SPEC.md` | CI architecture, quality gates, merge policy | Humans |
| `docs/PROJECT_STRUCTURE.md` | This file — the map itself | Humans |

**These five files exist in exactly one place.** There is no root-level mirror of any of
them. If you ever see `SER_PROJECT_SPEC.md` at the repository root again, that is a bug —
`scripts/check_artifacts.py::check_no_duplicate_canonical_docs` fails CI when it happens.

## 3. `.cursor/` — Research OS automation

```text
.cursor/
├── rules/            # Always-applied policy (workflow dispatcher, spec authority, gates, CI)
│   ├── 00-research-os.mdc
│   ├── 01-project-spec.mdc
│   ├── 02-validation-gates.mdc
│   ├── 03-training-workflow.mdc
│   └── 05-ci-policy.mdc
├── prompts/          # Reusable audit/review prompt templates (invoked by name, not auto-run)
│   ├── pre_change_audit.md
│   ├── pre_training_audit.md
│   ├── post_training_audit.md
│   ├── implementation_review.md
│   └── release_review.md
└── commands/         # Thin shell wrappers around scripts/workflow.py (no logic of their own)
    ├── audit.sh
    ├── pretrain.sh
    ├── posttrain.sh
    └── ci_local.sh
```

Rules are policy; prompts are reusable checklists; commands are one-line dispatchers. None
of the three layers duplicates logic that already lives in `scripts/workflow.py`.

## 4. `config/` — all hyperparameters

| File | Purpose |
|---|---|
| `config/config.yaml` | Production config. Every script defaults to this. |
| `config/ci.yaml` | CI-only synthetic-fixture config. Never used for thesis experiments. Points at `.ci_fixtures/`. |

No script hardcodes a hyperparameter, path, or magic number outside these two files.

---

## 5. Anti-duplication guarantee

`scripts/check_artifacts.py` (Gate 8, run by every workflow) enforces:

1. `REQUIRED_FILES` all exist (nothing is silently missing).
2. `check_no_notebooks()` — no `.ipynb` anywhere.
3. `check_no_duplicate_canonical_docs()` — none of `SER_PROJECT_SPEC.md`,
   `VALIDATION_PROTOCOL.md`, `WORKFLOW_GUIDE.md`, `CI_SPEC.md` exist at the repo root.
4. `check_no_full_training_in_ci_marker()` — `config/ci.yaml` never points at production
   `results/`.

If you add a new canonical doc, add it to `REQUIRED_FILES` **and** to §2 of this file in the
same change.

## 6. `src/ser/` — library code

| Module | Responsibility |
|---|---|
| `data.py` | Manifest parsing, label normalization, `Dataset` classes |
| `features.py` | Log-mel extraction, augmentation transforms |
| `splits.py` | Protocols A/B/C, speaker/corpus disjointness |
| `models.py` | Shared CNN backbone, CNN and CNN-BiLSTM heads (M0–M3) |
| `train.py` | Trainer loop, checkpointing, scheduler, early stopping |
| `metrics.py` | Accuracy, UAR, macro P/R/F1, confusion matrix |
| `analysis.py` | RQ1/RQ2/RQ3 table builders, results-frame normalization |
| `plotting.py` | All PNG figure generation (curves, confusion matrix, bar charts) |
| `utils.py` | Seeding, device selection, JSON/YAML I/O helpers |
| `audit.py` | Shared `GateResult`/`CheckResult`/report-rendering helpers for Research-OS scripts |

One responsibility per module. `audit.py` is Research-OS infrastructure and is never
imported by `train.py`/`models.py` — automation stays decoupled from the ML pipeline.

## 7. `scripts/` — CLI entry points

Grouped by pipeline stage (see `docs/WORKFLOW_GUIDE.md` for the full sequence):

| Stage | Script |
|---|---|
| Manifest | `prepare_manifest.py`, `inspect_manifest.py` |
| Features | `preprocess.py` |
| Splits | `make_splits.py` |
| CI fixtures | `prepare_ci_fixtures.py` |
| **Gate 1** Dataset | `validate_dataset.py` |
| **Gate 2** Features | `validate_features.py` |
| **Gate 3** Splits | `validate_splits.py` |
| **Gate 5** Smoke | `smoke_test.py` |
| **Gate 7** Reproducibility | `reproducibility_check.py` |
| **Gate 8** Artifacts | `check_artifacts.py` |
| Training | `run_experiments.py` |
| Pre-training aggregate | `workflow.py pre-training` (writes `PRE_TRAINING_AUDIT.md`) |
| Post-training health | `post_training_audit.py`, `audit_training.py` |
| Reporting | `gap_analysis.py`, `make_report.py` (thin wrapper over `gap_analysis.py`) |
| **Orchestrator** | `workflow.py` + `workflows.yaml` (defines step order for every workflow below) |

**One script per job.** `make_report.py` is intentionally a wrapper, not a duplicate, of
`gap_analysis.py` — it exists only for a friendlier CLI name.

## 8. `tests/` — pytest suite

Mirrors the module/script it covers 1:1 (`test_dataset.py` ↔ `validate_dataset.py`,
`test_features.py` ↔ `validate_features.py`, `test_models.py` ↔ `src/ser/models.py`, etc.).
No test file duplicates fixtures already defined elsewhere — CI-fixture builders come from
`scripts/prepare_ci_fixtures.py::build_ci_manifest`, imported, never copy-pasted.

## 9. Generated output directories — where results actually live

This is the split that used to be confusing. After the 2026-09-28 cleanup:

| Directory | Contents | Written by | Gitignored |
|---|---|---|---|
| `data/processed/` | Manifest, `.npy` log-mel features | `prepare_manifest.py`, `preprocess.py` | Yes |
| `data/splits/` | Split CSVs per protocol/seed | `make_splits.py` | Yes |
| `artifacts/runs/<run_id>/` | Per-run `config.yaml`, `history.csv`, `best_model.pt`, `metrics.json`, `report.txt` | `run_experiments.py` / `src/ser/train.py` | Yes |
| `artifacts/tensorboard/` | TensorBoard event files | `train.py` | Yes |
| `artifacts/plots/<run_id>/` | Per-run curve PNGs | `audit_training.py`, `plotting.py` | Yes |
| `artifacts/reports/` | **Research-OS audit reports only**: `validation_*.json`, `VALIDATION_*.md`, `workflow_*.md`, `training_health.json`, `manifest_inspect.*` | `validate_*.py`, `workflow.py`, `post_training_audit.py` | Yes |
| `results/` | **Research-facing outputs only**: `results.csv`, `rq1_*.csv`, `rq2_*.csv`, `rq3_*.csv`, `summary_by_protocol_model.csv`, `gap_analysis.md`, per-run `*.json`/`*_history.json` mirrors | `run_experiments.py`, `gap_analysis.py` | Yes |

**The rule going forward:** `artifacts/reports/` = tooling/automation evidence.
`results/` = thesis/paper-facing numbers. `gap_analysis.py` writes RQ tables to
`results/` only — it no longer mirrors them into `artifacts/reports/`. If you need both
directory purposes checked, run `python scripts/workflow.py post-training` (audits
`artifacts/`) and `python scripts/gap_analysis.py` (produces `results/`) separately.

## 10. Decision guide: "where do I put a new file?"

| I'm adding... | It goes in... |
|---|---|
| A new research claim / RQ / protocol | Edit `docs/SER_PROJECT_SPEC.md` (never a new doc) |
| A new validation gate | New script in `scripts/`, registered in `docs/VALIDATION_PROTOCOL.md` §-per-gate, wired into `scripts/workflows.yaml` |
| A new CLI stage | `scripts/<verb>_<noun>.py`, documented in `docs/WORKFLOW_GUIDE.md`, listed in §7 above |
| A new model responsibility | The matching module in `src/ser/` (§6) — do not create `src/ser/models2.py` |
| A new automation policy | `.cursor/rules/*.mdc` (append, don't fork existing rule files) |
| A new reusable audit prompt | `.cursor/prompts/*.md` |
| A generated report | `artifacts/reports/` (tooling) or `results/` (research) per §9 — never the repo root unless an existing rule names that exact root filename |

When in doubt: grep this file for the concept name before creating anything.
